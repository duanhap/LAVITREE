# BÁO CÁO TIẾN ĐỘ THỰC HIỆN DỰ ÁN – NGÀY 13/10/2026
## DỰ ÁN: LAVITREE / AGRI-GUARD

---

### 1. MỤC TIÊU TRONG NGÀY

Hoàn thiện truy cập hệ thống LAVITREE qua tên miền riêng `lavitree.io.vn`, thiết lập Nginx reverse proxy trên EC2 và bật HTTPS bằng chứng chỉ TLS.

### 2. HẠ TẦNG ĐÃ CÓ TRƯỚC KHI THỰC HIỆN

- Máy chủ AWS EC2 `lavitree-server`, Ubuntu 24.04, instance `t3.micro`, đang chạy tại public IPv4 `54.79.31.235`.
- Docker Compose đang chạy ứng dụng; web portal được publish trên host port `3000` (container Nginx bên trong phục vụ port 80). Core API được publish trên host port `5000`.
- GitHub Actions self-hosted runner đã được thiết lập từ trước để tự động triển khai khi cập nhật nhánh `main`.
- Tên miền đã đăng ký là `lavitree.io.vn` (không phải DuckDNS). DNS có hai bản ghi A:
  - `lavitree.io.vn` (`@`) → `54.79.31.235`
  - `www.lavitree.io.vn` (`www`) → `54.79.31.235`

### 3. CÔNG VIỆC ĐÃ THỰC HIỆN

#### 3.1. Xác minh DNS và địa chỉ EC2

Từ Windows PowerShell, chạy `nslookup` cho cả tên miền gốc và `www`. Cả hai đều phân giải về `54.79.31.235`, khớp với Public IPv4 hiển thị trên EC2 đang chạy.

#### 3.2. Cài Nginx trên Ubuntu host

SSH vào máy chủ bằng tài khoản `ubuntu` và PEM trong thư mục `AWS`, sau đó cài Nginx cùng Certbot/nginx plugin. Trạng thái systemd được xác nhận:

- `nginx.service`: `active (running)`
- Dịch vụ được bật khi hệ điều hành khởi động (`enabled`)

Nginx host là reverse proxy phía trước Docker web container. Nó hoạt động độc lập với Nginx nằm bên trong container web và với GitHub Actions runner.

#### 3.3. Cấu hình reverse proxy cho tên miền

Tạo site Nginx host cho `lavitree.io.vn` và `www.lavitree.io.vn`; các request được chuyển tiếp tới `http://127.0.0.1:3000`. Cấu hình được kiểm tra bằng `nginx -t` và nạp lại dịch vụ.

Đã xác nhận bằng trình duyệt rằng cả hai URL HTTP sau đều hiển thị giao diện LAVITREE:

- `http://lavitree.io.vn`
- `http://www.lavitree.io.vn`

#### 3.4. Security Group cho web

Kiểm tra inbound rules của Security Group EC2. Các cổng sau đang mở tới `0.0.0.0/0`:

- TCP 80 (HTTP)
- TCP 443 (HTTPS)

Do rule 443 đã tồn tại, không cần tạo thêm rule HTTPS.

#### 3.5. HTTPS

Sau khi cấu hình Nginx HTTP và xác nhận DNS, Certbot được dùng với Nginx plugin để cấp/cài chứng chỉ cho tên miền. Người dùng xác nhận truy cập thành công:

- `https://lavitree.io.vn`

### 4. TRẠNG THÁI HIỆN TẠI

- DNS `@` và `www` cùng trỏ đúng về EC2 `54.79.31.235`.
- Nginx host đang chạy và tự khởi động cùng Ubuntu.
- HTTP qua cả tên miền gốc và `www` đã hiển thị ứng dụng.
- HTTPS tại `https://lavitree.io.vn` đã được người dùng xác nhận hoạt động.
- Docker Compose và GitHub Actions runner tiếp tục là các dịch vụ hiện hữu trên EC2; reverse proxy host chuyển request web tới cổng 3000 của Docker.

### 5. VIỆC NÊN KIỂM TRA TIẾP

1. Mở `https://www.lavitree.io.vn` để xác nhận chứng chỉ bao gồm cả tên miền `www`.
2. Trên EC2, chạy `sudo certbot certificates` để xem chứng chỉ và danh sách domain đã cấp.
3. Kiểm tra gia hạn mô phỏng bằng `sudo certbot renew --dry-run`.
4. Sau khi xác nhận truy cập tên miền ổn định, cân nhắc thu hẹp quyền truy cập public trực tiếp vào các cổng ứng dụng Docker như 3000, 5000 và 8000; chỉ để người dùng web đi qua 80/443. Cổng SSH 22 cũng nên giới hạn theo IP quản trị.
