### 3. CHI TIẾT KỸ THUẬT & CÁC THAY ĐỔI TRỌNG TÂM

#### 3.1. Phân hệ Tra cứu Vật tư Thông minh (`TASK-17`)
- **Tô đậm & Cắt ngữ cảnh Bằng chứng (`product-research.ts`)**:
  - Khi một vật tư được đề xuất từ bài báo, hệ thống trích xuất câu chứa tên vật tư đó cùng các câu liền kề trước/sau, tô đậm từ khóa bằng component `HighlightedText`.
  - Nhận diện các trường hợp đặc biệt: Chế phẩm tự pha tại chỗ (`HOMEMADE`), Giống kháng bệnh (`SEED`), hoặc Biện pháp canh tác (`PRACTICE`) để đưa ra khuyến cáo phù hợp thay vì ép thành thuốc hóa học thương phẩm.
- **Gom nhóm Đoạn trích theo Bài báo & Giữ trạng thái Gợi ý**:
  - Gộp các đoạn trích có cùng URL bài báo và cùng loại bệnh vào chung một nhóm hiển thị trong modal chi tiết.
  - Sửa đổi logic `MedicinesController.CreateMedicine`: Khi tạo một sản phẩm mới từ nhóm gợi ý, server chỉ đóng các gợi ý thuộc về bệnh đã được gán; các gợi ý cho các bệnh khác vẫn được giữ nguyên ở trạng thái `PENDING` (`suggestions_kept_pending = N`), giúp Admin có thể tiếp tục liên kết bổ sung sau này mà không bị mất dấu.

#### 3.2. Cấu trúc Phiếu Cách dùng Vật tư (`UsageProfile`) - Chuẩn bị Lịch phun thuốc
- **Thiết kế Entity CSDL**:
  ```csharp
  public class UsageProfile
  {
      public NumberRange? DosePer16L { get; set; }     // Liều lượng pha bình 16 lít (ml hoặc g)
      public NumberRange? DosePer25L { get; set; }     // Liều lượng pha bình 25 lít
      public AreaDose? DosePerArea { get; set; }       // Liều theo diện tích (kg/ha, lít/sào)
      public string? TimeOfDay { get; set; }           // "Sáng sớm", "Chiều mát"
      public int? TimesPerDay { get; set; }            // Số lần phun trong ngày
      public NumberRange? IntervalDays { get; set; }   // Cách nhau số ngày giữa các lần phun
      public int? MaxTimesPerSeason { get; set; }      // Tối đa số lần phun trong một vụ canh tác
      public string? WeatherNote { get; set; }         // Lưu ý thời tiết (tránh mưa, nắng gắt)
      public string? SafetyNote { get; set; }          // Lưu ý đồ bảo hộ lao động
  }
  ```
- **Lưu trữ CSDL**: Lưu dưới dạng cột `jsonb` trong bảng `Products` qua bản migration EF Core `20261116192621_AddProductUsageProfile`.
- **Cơ chế Prompt Gemini Đa Nguồn**:
  - Thiết kế prompt ở chế độ Dev: Yêu cầu AI tìm kiếm thông số kỹ thuật thực tế từ các nguồn tiếng Việt uy tín (khuyennongvn.gov.vn, cucthucvat.gov.vn, nhà sản xuất); trích xuất cấu trúc JSON có đầy đủ `usage_profile`, mô tả chuyên sâu 4 ý, và danh sách nguồn kèm câu trích dẫn nguyên văn chứa số liệu.
  - Khối "Hướng dẫn sử dụng" tự động ghép nối các trường trong `UsageProfile` theo nhãn cố định để Trợ lý AI Lavi có thể đọc hiểu và tư vấn chính xác cho người nông dân.

#### 3.3. Bộ Đối soát Trích dẫn Nguyên văn (`TASK-18-R4`, `R5`)
- **Kiểm soát ảo giác số liệu**:
  - Quản trị viên bấm nút "Kiểm tra trích dẫn" $\rightarrow$ Frontend gửi danh sách các câu trích dẫn và URL nguồn lên Core API (`POST /api/v1/knowledge/verify-quotes`).
  - Core API tải mã HTML công khai của trang web bằng dịch vụ chống SSRF `FetchPublicHtmlAsync`.
  - Lớp dịch vụ `QuoteMatcher.cs`:
    - Chuẩn hóa văn bản Unicode (`FormKD`, chuyển `m²` thành `m2`), loại bỏ thẻ HTML, chuyển về chữ thường không dấu.
    - So khớp trích dẫn: Đánh giá tỷ lệ bao phủ ký tự. Nếu đạt $\ge 80\%$ xếp loại `PARTIAL`, khớp chính xác xếp loại `FOUND`, không tìm thấy xếp loại `NOT_FOUND`.
    - **Kiểm tra con số**: Bắt buộc các con số xuất hiện trong câu trích của AI phải tồn tại thực sự trong phân đoạn văn bản của trang gốc, ngăn chặn trường hợp AI "bịa" ra liều lượng phun thuốc.
