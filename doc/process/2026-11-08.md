# BÁO CÁO SỰ CỐ & XỬ LÝ HẠ TẦNG – NGÀY 08/11/2026
## DỰ ÁN: LAVITREE – Sự cố deploy agent-service làm treo máy chủ AWS EC2

---

### 1. HIỆN TƯỢNG

- Job GitHub Actions `Deploy to AWS EC2` (runner self-hosted `lavitree-ec2-runner`) dừng ở bước build `agent-service`:
  `[agent-service 6/8] RUN python -c "...SentenceTransformer('BAAI/bge-m3')"`. Log không có dòng lỗi; các dòng `WARNING`/`FutureWarning` chỉ là cảnh báo.
- Sau đó toàn bộ cổng của EC2 `lavitree-server` (22, 80, 3000, 5000) không phản hồi, dù AWS Console vẫn báo `Running`.
- Runner trên GitHub chuyển sang `Offline`; các lần deploy sau kẹt ở `Waiting for a runner`.

### 2. NGUYÊN NHÂN

1. **Hết RAM (nguyên nhân chính).** Máy là `t3.micro` (1GB RAM, có sẵn 3GB swap). Bước build nạp hẳn model `bge-m3` (~2.2GB) vào RAM trong khi 6 container vẫn chạy, máy dùng swap quá mức và treo cứng, kéo theo mất SSH và runner.
2. **Dockerfile tải thừa và nhân đôi dung lượng.**
   - `SentenceTransformer(...)` tải cả thư mục `onnx/` (2.16GB) không dùng tới.
   - `chown -R ... /opt/hf-cache` ở layer cuối chép lại toàn bộ cache model thêm một lần.
3. Agent-service đang chạy trên server là image cũ từ 4 tuần trước (262MB, chưa có bge-m3); bản có bge-m3 chưa từng build thành công trên EC2.

### 4. SỬA DOCKERFILE AGENT-SERVICE

- Tải model bằng `huggingface_hub.snapshot_download` (chỉ tải file, **không nạp vào RAM** lúc build).
- Bỏ `onnx/*`, ảnh minh hoạ, `colbert_linear.pt`, `sparse_linear.pt`; chỉ tải 12 file (~2.2GB thay vì ~4.4GB).
- Tạo user `lavitree` và cấp quyền `/opt/hf-cache` **trước** khi tải, tải bằng chính user đó, bỏ `chown -R` sau cùng để không sinh layer chép đôi.
- Giữ nguyên model `BAAI/bge-m3`, `HF_HOME`, chế độ offline lúc chạy và chạy bằng user thường.

**Kết quả build thử trên EC2 (tag riêng `lavitree-agent-test`, không đụng container đang chạy):**
- Cài thư viện xong, bước tải model 12 file mất 21,7 giây.
- Bước giải nén image **thất bại vì đầy ổ đĩa** (`no space left on device`, ổ 24GB lên 100%). Docker trên máy dùng containerd snapshotter nên mỗi image chiếm gần gấp đôi: một bản nén và một bản đã giải nén.
- Đã xoá ngay image thử và build cache (thu hồi ~3GB), ổ còn trống 13GB. Postgres không ghi lỗi, `pg_isready` OK, web trả 200.
- Sau khi mở rộng EBS lên 40GB (phân vùng tự nới, trống 28GB), build lại thành công. Chạy container thử với `--network none --memory 4g`: model nạp từ image, chạy bằng user `10001`, `dim 1024`, encode một câu tiếng Việt ra `(1, 1024)`, nạp + encode mất 8,8 giây. Dòng cảnh báo "cache for model files in Transformers v4.22.0" xuất hiện nhưng không ảnh hưởng kết quả.
- Đã xoá image thử, giữ build cache (~6GB) để lần deploy thật dùng lại; ổ còn trống 22GB.
