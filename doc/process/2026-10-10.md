### 1. TỔNG QUAN CÔNG VIỆC TRONG NGÀY
Hôm nay nhóm đã hoàn thành toàn diện việc thiết kế kiến trúc, khởi tạo bộ khung mã nguồn gốc (**Base Code**) Monorepo, thiết lập **Cơ sở dữ liệu đám mây Supabase**, và triển khai môi trường **Cloud AWS EC2** tối ưu hóa bộ nhớ cho hệ sinh thái dự án **Lavitree**.

Hệ thống bao gồm đầy đủ 5 thành phần công nghệ theo đúng yêu cầu đề tài và tài liệu đặc tả ([BRD.md](file:///d:/PTIT%20Do%20An/BRD.md), [PRD.md](file:///d:/PTIT%20Do%20An/PRD.md), [PMP.md](file:///d:/PTIT%20Do%20An/PMP.md), [cloud.md](file:///d:/PTIT%20Do%20An/cloud.md)):
1. **Core Backend**: ASP.NET Core 8 Web API (Clean Architecture).
2. **AI Microservice**: Python FastAPI (Inference PyTorch ResNet-18 + XAI Grad-CAM).
3. **Bonus Agent**: Python FastAPI (Agri-Agent RAG tư vấn khuyến nông & an toàn PHI).
4. **Mobile App**: Kotlin + Jetpack Compose (Android Native).
5. **Web Portal**: React 18 + Vite + TypeScript (Farmer Portal + Admin Dashboard).
6. **Cloud & Database**: Supabase PostgreSQL (Singapore) + AWS EC2 (Sydney - $120 Credit).

#### 2.1. Backend 1: ASP.NET Core 8 Web API (`backend/core-api`)
* **Khởi tạo Solution & Phân tầng Clean Architecture**:
  - `Lavitree.Domain`:
    - Tạo `BaseEntity.cs` quản lý dấu thời gian (`CreatedAt`, `UpdatedAt`) và cờ xóa mềm (`IsDeleted`).
    - Xây dựng **10 thực thể cốt lõi (Domain Entities)** chuẩn hóa theo ERD:
      1. `User.cs`: Quản lý tài khoản và phân quyền (`FARMER`, `ADMIN`, `EXPERT`).
      2. `PlantCategory.cs`: Danh mục 14 loài cây trồng.
      3. `Disease.cs`: Danh mục 38 lớp bệnh cây với mã lớp `ClassCode` duy nhất.
      4. `TreatmentPlan.cs`: Phác đồ xử lý 3 bước (Cắt tỉa, Phun thuốc, Bón phục hồi).
      5. `Product.cs`: Danh mục vật tư nông nghiệp, hoạt chất, hướng dẫn pha bình 16L.
      6. `DiseaseProduct.cs`: Bảng liên kết trung gian N-N giữa bệnh và thuốc BVTV đặc trị.
      7. `DiagnosisRecord.cs`: Lưu vết nhật ký các ca chẩn đoán của người dùng.
      8. `Order.cs` & `OrderItem.cs`: Quản lý đơn hàng mua vật tư điều trị (COD / QR Pay).
  - `Lavitree.Application`:
    - Định nghĩa DTOs kết quả chẩn đoán (`DiagnosisResultDto`, `TreatmentStepDto`, `ProductDto`, `AiPredictionResponse`).
    - Khai báo giao diện dịch vụ `IAiVisionService` cho phép tầng ứng dụng gọi sang module AI.
  - `Lavitree.Infrastructure`:
    - Cấu hình `LavitreeDbContext.cs` với Entity Framework Core, kết nối cơ sở dữ liệu PostgreSQL (hỗ trợ Supabase Cloud theo tài liệu `cloud.md`).
    - Triển khai `AiVisionService.cs` sử dụng `HttpClient` gửi dữ liệu multipart/form-data sang FastAPI endpoint nội bộ.
  - `Lavitree.Api`:
    - Cài đặt `DiagnoseController.cs`: Tiếp nhận ảnh lá từ Client $\rightarrow$ Chuyển tiếp sang AI Microservice phân tích $\rightarrow$ Tự động truy vấn Database lấy phác đồ điều trị 3 bước và thuốc đặc trị $\rightarrow$ Lưu bản ghi `DiagnosisRecord` $\rightarrow$ Trả kết quả trọn gói trong 1 request.
    - Cài đặt `DiseasesController.cs`: Cung cấp API tra cứu cẩm nang bệnh học.
    - Cấu hình Swagger UI, Dependency Injection, CORS và `Program.cs`.
  - **Kết quả nghiệm thu**: `dotnet build` thành công: **0 Warning, 0 Error**.

#### 2.2. Backend 2: AI Vision Microservice (`backend/ai-service`)
* **Di chuyển Checkpoint Mô hình**:
  - Đã tích hợp trọng số huấn luyện ResNet-18 `best_plant_model.pt` (kích thước ~44.8 MB) và file nhãn `class_indices.json` (38 phân lớp cây-bệnh).
* **Module Giải thích Mô hình XAI (Explainable AI)**:
  - Viết module `gradcam.py`: Đăng ký hooks trên lớp tích chập cuối cùng (`layer4[-1]`) của ResNet-18, trích xuất gradients và activations để sinh bản đồ nhiệt (Heatmap).
  - Phủ ảnh nhiệt lên ảnh gốc với độ trong suốt tùy chỉnh và mã hóa kết quả sang Base64 để hiển thị trực tiếp trên giao diện Client.
* **Module Dự đoán & Lọc Bất định (Uncertainty Handling)**:
  - Viết `predictor.py`: Tiền xử lý chuẩn hóa ảnh PyTorch (Resize 224x224, Normalize theo ImageNet).
  - Áp dụng **ngưỡng tin cậy $70\%$ (Confidence Threshold)** theo đúng tiêu chí trong BRD & PRD: Tự động gắn cờ cảnh báo `is_uncertain: true` khi độ tự tin $< 70\%$ nhằm ngăn chặn phán đoán bừa bãi khi người dùng chụp ảnh mờ hoặc ngoài miền dữ liệu.
* **FastAPI Entrypoint**:
  - Endpoint `POST /api/v1/ai/predict`: Kiểm tra định dạng ảnh (JPEG, PNG, WebP) và trả về nhãn dự đoán, độ tin cậy, top-3 dự đoán cùng ảnh nhiệt Grad-CAM.
  - Endpoint `GET /health` giám sát trạng thái dịch vụ.

  - Sử dụng Region **Asia Pacific (Sydney) `ap-southeast-2`** được phân bổ theo gói credit.
* **Khởi tạo Máy ảo EC2 (`lavitree-server`)**:
  - AMI: **Ubuntu Server 24.04 LTS (x86_64)**.
  - Instance Type: **`t3.micro`** (2 vCPUs, 1 GiB RAM).
  - Storage: **25 GiB gp3** SSD (hoàn toàn miễn phí trong hạn mức 30GB).
  - Security Group: Mở sẵn các cổng 22 (SSH), 80 (HTTP), 443 (HTTPS), 3000 (Web), 5000 (Core API), 8000 (AI Vision).
* **Khắc phục Lỗi Phân quyền SSH Key trên Windows**:
  - Xử lý lỗi bảo mật `WARNING: UNPROTECTED PRIVATE KEY FILE! Permissions for 'lavitree-key.pem' are too open` bằng lệnh PowerShell `icacls`, thiết lập quyền đọc duy nhất cho tài khoản người dùng máy tính.
  - Kết nối thành công vào máy chủ Ubuntu qua lệnh: `ssh -i "lavitree-key.pem" ubuntu@54.79.31.235`.
* **Cơ chế Cứu mạng RAM (Memory Swap Optimization)**:
  - Khắc phục nguy cơ treo máy do hết RAM (Out of Memory - OOM) trên cấu hình 1GB RAM của `t3.micro`.
  - Kích hoạt thành công **3.0 GiB Swap Memory** từ ổ SSD vào hệ thống:
    ```bash
    Mem:  911Mi total, 400Mi used
    Swap: 3.0Gi total (Sẵn sàng phục vụ Docker)
    ```
  - Cài đặt hệ sinh thái Docker Engine, Docker Compose v2 và Git trên máy chủ Ubuntu.

#### 2.8. Tối ưu Đóng gói Docker & Khắc phục Lỗi Triển khai
1. **Sửa lỗi Build TypeScript Web Frontend**:
   - Khắc phục lỗi `TS17004: Cannot use JSX unless the '--jsx' flag is provided`: Bổ sung `"jsx": "react-jsx"` vào `tsconfig.json`.
   - Nới lỏng strict linting (`noUnusedLocals: false`) và dọn dẹp các icon import thừa (`BookOpen`, `AlertCircle`, `FileText`, `Users`).
   - Kiểm tra build cục bộ `npm run build`: Thành công 100% trong 2.01 giây.
2. **Sửa lỗi Tràn Ổ cứng `[Errno 28] No space left on device` ở AI Service**:
   - Nguyên nhân: PyTorch mặc định tải gói cài đặt NVIDIA CUDA GPU nặng hơn 4GB–5GB trên máy ảo CPU.
   - Giải pháp: Chuyển đổi `Dockerfile` sang sử dụng **PyTorch CPU-only siêu nhẹ (~180MB)** qua kho lưu trữ chính thức `--index-url https://download.pytorch.org/whl/cpu`.
   - Giúp giảm dung lượng build hơn 90%, tiết kiệm ổ cứng và tăng tốc độ build gấp 10 lần.
3. **Tối ưu hóa Docker Compose cho Cloud**:
   - Loại bỏ container `postgres-db` chạy cục bộ không cần thiết, chuyển cấu hình kết nối trực tiếp đến **Supabase Cloud** qua biến môi trường.
   - Tiết kiệm thêm ~100MB RAM và tài nguyên CPU của máy ảo EC2.
   - Đóng gói file nén triển khai `lavitree.tar.gz` dung lượng tinh gọn (~41MB) để upload qua `scp`.
